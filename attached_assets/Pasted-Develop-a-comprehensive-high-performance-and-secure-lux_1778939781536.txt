Develop a comprehensive, high-performance, and secure luxury e-commerce platform for "Shamim Forever," encompassing a customer-facing website and a powerful administrative control panel. The entire project should embody a minimalist, elegant, black and gold aesthetic, reflecting the brand's high-end perfume, cosmetics, and jewelry offerings.
​1. Project Overview
​This project aims to create a full-stack web application that serves as the digital backbone for the "Shamim Forever" luxury brand. It will provide a seamless shopping experience for customers and an intuitive, robust management system for administrators to control all aspects of the business.
​2. Brand Identity & Design Principles
​Aesthetic: Ultra-minimalist, elegant, luxurious. Predominantly black and gold color palette with rich dark overtones. Clean typography. High-resolution imagery.
​Logo Integration: The provided "SF" monogram with the diamond crown and "SHAMIM FOREVER" text must be consistently integrated and embossed/engraved where appropriate.
​Responsiveness: Fully responsive design for optimal viewing on all devices (desktop, tablet, mobile).
​Performance: Optimized for fast loading times, edge-caching for 8K product photography, and smooth user interactions.
​3. Recommended Technology Stack
​Front-end (Customer & Admin UI): Next.js (React.js for UI, Server-Side Rendering/Static Site Generation for SEO and performance) with TypeScript and Tailwind CSS for styling.
​Back-end (API & Logic): Node.js with NestJS (for structured, scalable API development) or Python with FastAPI. Use TypeScript for Node.js.
​Database: PostgreSQL (for relational product, order, user data) and Redis (for shopping cart caching and session management).
​Authentication: JWT (JSON Web Tokens) for secure API authentication with HTTP-only cookies, and Role-Based Access Control (RBAC).
​Storage & CDN: Cloudinary or AWS S3 integrated with a CDN for lightning-fast delivery of ultra-premium, high-resolution media assets.

​6. System Architecture & Required APIs
​The system must run on a secure, RESTful API architecture connecting the front-end to the back-end and necessary third-party services:
​A. Internal Application APIs
​Authentication & Access: POST /api/auth/login, POST /api/auth/register, GET /api/admin/audit-logs (Protected).
​Product Catalogue: GET /api/products (With advanced filtering/sorting), POST /api/products/scent-finder (Processes quiz logic).
​Order Engine: POST /api/orders/create (Handles custom engraving data strings), GET /api/orders/track/[orderId].
​Cart & Stock Validation: POST /api/cart/validate (Real-time check against database stock before checkout processing).
​B. Third-Party Integrations & APIs
​Payment Gateways: Stripe API / PayPal API for global card settlements and regional payment methods.
​Logistics & Fulfillment: DHL / FedEx or ShipEngine API for automated shipping labels, customs documentation, and live transit webhooks.
​Communications: Twilio / WhatsApp Business API for automated transaction receipts, delivery status updates, and concierge reminders.
​Media Processing: Cloudinary or AWS S3 API for edge-optimized delivery of heavy graphic assets without sacrificing site speed.
​7. Database Schema (Key Entities - PostgreSQL)
​Design a robust relational database schema with the following core tables and their relationships:
​Users: id, name, email, password_hash, role (customer, admin), created_at, updated_at.
​Products: id, name, description, price, category_id, stock_quantity, sku, image_urls (JSONB), has_engraving_option (boolean), created_at, updated_at.
​Batches: id, product_id, batch_number, manufacture_date, expiry_date, quantity.
​Categories: id, name, description.
​Orders: id, user_id, total_amount, currency, status, shipping_address, payment_status, tracking_number, created_at, updated_at.
​OrderItems: id, order_id, product_id, quantity, unit_price, custom_engraving_text (nullable text).
​Reviews: id, product_id, user_id, rating, comment, created_at.
​Wishlists: id, user_id, product_id, created_at.
​AdminUsers: id, username, email, password_hash, role_id, created_at, updated_at.
​Roles & Permissions: Tables managing Access Control (Roles, Permissions, RolePermissions junction table).
​Suppliers & RawMaterials: Management tables for procurement tracking.
​8. Security & Deployment Considerations
​Data Encryption: Passwords must use Argon2id or bcrypt hashing. All traffic must be enforced over HTTPS with TLS 1.3. Sensitive parameters must use data encryption at rest.
​Input Cleansing: Strict schema validation on inputs using libraries like Zod or Joi to prevent SQL Injection and XSS attacks.
​Rate Limiting: Protect crucial endpoints (/api/auth/*, /api/checkout/*) against brute-force attacks using rate-limiting middleware.
​Deployment Target: Optimized for repository maintenance via GitHub (monorepo format). Simple environment setup using a .env configuration file managing API keys, database credentials, and production URLs securely.
​Execution Step: Begin by implementing the repository boilerplate, setting up the PostgreSQL database migration scripts, and creating a pristine home screen layout focusing strictly on the premium luxury black-and-gold visual theme.
